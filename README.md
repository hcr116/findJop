# BOSS 岗位追踪器

每天自动帮你翻 BOSS 直聘，**只告诉你没见过的岗位**，不再手动来回刷同一批公司。

- 数据全部存在你自己的电脑上，不联网、不上传
- 别人用这个工具，用的是他自己的库，**看不到你的任何记录**
- 支持多组关键词、城市、薪资、排除词，每个岗位带薪资和 JD 正文

---

## 快速开始

### 1. 装 Node.js（只需一次）

到 <https://nodejs.org> 下载 LTS 版本安装。装完在命令行里 `node -v` 能出数字就行。

### 2. 登录（只需一次）

```bash
node src/cli.mjs login
```

会弹出一个专门的 Edge 窗口，你在里面**扫码或密码登录 BOSS 直聘**，登录成功后**把这个窗口关掉**，程序会自动检测到并保存登录态。

> 这一步为什么必须手动：BOSS 未登录时只给看第 1 页，翻页会被拦。登录动作发生在完全正常的浏览器里，不会有任何风控问题；之后工具只是复用这份登录态。

### 3. 配置你要找什么工作

```bash
node src/cli.mjs serve --open
```

**桌面上有「BOSS岗位追踪」快捷方式**，双击等同于上面这条命令（图标是 %APPDATA%\boss-jobs\icon.ico，大肥鱼那只）。
关掉弹出的黑窗口就等于停掉服务。

> ⚠️ 图标**不能**放在项目目录里。`.lnk` 的图标路径太长（超过约 90 字符）时，
> Windows 外壳会静默加载失败、显示成白纸图标——而且极难查：GDI+ 和 ExtractIconEx 都能正常读出这个 ico。
> 所以图标固定放在 `%APPDATA%\boss-jobs\icon.ico`（57 字符），项目里的 `icon.png` 只是源图。

浏览器会打开 `http://127.0.0.1:7799`，点「搜索配置」添加，比如：

| 名称 | 关键词 | 城市 | 薪资(K/月) | 经验 | 学历 | 页数 | 排除词 |
|---|---|---|---|---|---|---|---|
| 战斗策划-上海 | 战斗策划 | 上海 | 20–45 | 3-5年,5-10年 | 本科 | 3 | 外包,驻场,销售 |
| 游戏策划-上海 | 游戏策划 | 上海 | 15–40 | 留空 | 留空 | 3 | 外包,驻场 |

关键词、经验、学历都支持逗号分隔多个值（命中任一即可）。留空表示不限。

### 筛选规则（几个刻意的取舍）

- **薪资**按「区间是否有交集」判断：岗位 20-40K、你期望 25-50K，有交集就保留。
- **日薪岗**（实习，`200-300元/天`）不参与月薪比较，不会被薪资条件误杀。
- **面议 / 薪资未知**的岗位一律保留，不会因为读不到薪资就丢掉。
- **经验/学历带「不限」「应届」**的一律保留，避免把人筛没。
- **排除词**匹配岗位标题 + 公司名，命中就跳过（不入库，不占你的列表）。

### 个人档案：先告诉它「你是谁」

搜索配置回答的是**我要找什么**，档案回答的是**我是谁**。同一个关键词，
工作几年的社畜和应届生该看到的岗位不一样 —— 没有档案时，实习、校招这类会混进列表，
还白占每轮有限的 JD 抓取额度。

界面上点「我的档案」：

| 字段 | 作用 |
|---|---|
| 身份 | 选一下自动带出默认规则：**社畜**默认剔实习/校招；**应届生**默认全收；**转行中**不拦低经验岗 |
| 工作年限 | 「经验要求明显低于我」按它算（例：填 5 年，`1-3年` 的岗位会被判为降级） |
| 最高学历 | 只有勾了「学历要求高于我」才用得上 |
| 自动剔除 | 实习岗 / 校招应届专属 / 经验偏低 / 学历不够 —— 四个独立开关 |
| 额外排除词 | 命中标题或公司名就跳过（外包、驻场…） |

规则在两个地方生效：

- **抓取时**：不符合的直接不入库（省 JD 额度，日志里写「档案：实习岗」）。
- **老数据**：点「按档案重扫现有岗位」，把库里已经进来的标成 `filtered`（档案滤掉）。
  只改状态、不删数据；**档案放宽后再重扫一次，它们会自动放回来**。
  想看被挡了什么，列表上面点「档案滤掉」那个按钮。

换个人用：他装一份、填自己的档案就行 —— 档案和数据都存在本机，谁也看不到谁的。

### 4. 抓一轮试试

界面上点「立即抓取一轮」，或命令行：

```bash
node src/cli.mjs run
```

### 5. 挂上定时任务

```bash
node src/cli.mjs schedule install 10:00,20:00
```

每天 10:00 和 20:00 自动跑，跑完弹系统通知。删除用 `node src/cli.mjs schedule remove`。

> 定时任务只在电脑开机、且已登录 Windows 时会跑。关机时那一次会跳过。

**注意：默认是「轮转」模式**——每轮只跑一个关键词，下一次自动换下一个。
因为实测一轮累计 7~9 次请求就会被风控拦，一次跑两个关键词必然第二个失败。
所以配 2 个关键词 + 每天 2 次定时，刚好全覆盖。
想一次跑全部：`node src/cli.mjs run --all`（慢，且更容易被拦）。

## 它怎么判断「新岗位」

| 规则 | 说明 |
|---|---|
| **硬去重**（始终生效） | `job_id` 从没见过 → 真·新岗位，会提醒你 |
| **软去重**（默认关） | 同公司 + 同标题在 N 天内重发 → 标「疑似重发」，仍然入库但不强调 |

你在意的「同一家公司反复出现」，界面上每个岗位都会显示**这家公司你之前见过几个岗**，点开详情能看历史。

## 标签（自己给岗位和公司贴记号）

点开任意岗位，抽屉里有个「标签」区域，输入任意名字回车就加上，比如：

- 打在**岗位**上 → 只影响这一条：`已投递未过`、`已投递面过`、`待投递`
- 打在**公司**上 → 这家公司**所有岗位**都自动带上：`外包`、`老逼登厂`、`996`

界面上两种标签长得不一样：

| | 样式 | 含义 |
|---|---|---|
| 岗位标签 | 实心青绿 | 你给这一条标的 |
| 公司标签 | 虚线灰 | 这家公司整体带过来的 |

一个目标可以挂任意多个标签，标签名完全自定义（输入即创建），不用提前建。
顶部的「全部标签」下拉可以按标签筛岗位，选项后面括号里是该标签被用了多少次。

> 标签存在本机数据库里，跟岗位数据一起。删标签会把所有引用一起清掉。

## 匹配度评分

每个岗位右上角有个分数（0–100），工具栏可以在「最新」和「匹配度」之间切换排序。

分数是**规则算出来的，不是 AI 猜的**，好处是每一分都能解释。点开详情能看到分项：

| 维度 | 满分 | 怎么算 |
|---|---|---|
| 薪资匹配 | 35 | 岗位薪资区间和你的期望区间重合得越好越高；无交集直接 0 |
| 关键词命中 | 35 | 标题命中满分，技能标签命中 80%，JD 正文命中 60% |
| 新鲜度 | 20 | 今天入库满分，10 天线性衰减到 0 |
| HR 活跃 | 10 | HR 近期在线满分，否则很低 |

**拿不到数据的维度给中性分，不给 0**：未登录时薪资是空的、岗位写"面议"、
日薪实习岗，都不会因为读不到薪资就被冤枉成低分。

> 注意：分数依赖你的搜索配置（薪资区间、关键词）。没配薪资期望时，
> 薪资维度只给中性分，这时候分数主要靠关键词和新鲜度。

## 投递进度（时间线）

点开岗位，抽屉里有个「投递进度」区，九个阶段：

```
已投递 → 简历筛选中 → 一面 → 二面 → 三面 → HR面 → 拿到 Offer
                                                  ↘ 挂了 / 我放弃了
```

点一下按钮就记一条，可以带备注（比如「约了下周三下午一面」）。有几条特性：

- **是流水不是状态**：同一岗位可以记多次，完整保留「什么时候投的、什么时候一面的」
- **最新一条在最上面**，当前阶段按钮会高亮
- 记「已投递」时，岗位状态会自动从「未处理」变成「已投递」
- 记错了可以点记录右侧的 ✕ 删掉

> 为什么不复用原来的「已投递」开关：那个是「这条要不要看」的开关，
> 而投递进展是会发生很多次的过程，用单一状态会丢掉历史。

## 排除词会自己长

你「忽略」一个岗位时，其实是在告诉系统「这种我不想要」。

打开「搜索配置」，底部有一块「从已忽略的岗位提炼排除词」——它把你忽略过的岗位里的
**公司名**统计出来，点一下 + 就加进所有配置的排除词里，下次抓到这家公司直接跳过。

这样忽略动作本身会让下一轮更准，而不是白点一下。

## 数据在哪

```
%APPDATA%\boss-jobs\
├── data.db              ← SQLite 数据库（你的所有岗位记录）
├── browser-profile\     ← 登录态（Edge 专用配置）
├── login-state.json     ← 登录状态标记
├── runs\                ← 每次运行的过程记录，出问题可查
└── schedule.log         ← 定时任务的输出
```

**换电脑或备份，直接拷整个 `boss-jobs` 文件夹即可。**
删掉 `browser-profile` 等于退出登录，需要重新扫码。

## 风控红线（重要）

BOSS 有反自动化检测，这个工具刻意做得**很慢**：

| 项 | 默认值 | 说明 |
|---|---|---|
| 每轮每关键词翻页 | 最多 3 页 | 调高 = 更容易被拦 |
| 翻页间隔 | 6–12 秒随机 | |
| 每个详情的间隔 | 4–8 秒随机 | |
| 每轮最多抓几个详情 | 5 个 | 详情请求最容易触发风控 |
| 每天运行次数 | 建议 1–2 次 | |

碰到 `code=37`（安全验证）会**立刻放弃整轮**，不会硬试。歇几分钟再跑通常就恢复了；实在不行重跑 `login`。

**不要**把频率调高。代价是账号被风控，得不偿失。

## 命令速查

```bash
node src/cli.mjs serve [--open]     # 起本地网页
node src/cli.mjs run [id|--all]     # 立刻抓一轮（默认轮转，一次只跑一个关键词）
node src/cli.mjs login              # 登录 / 重新登录
node src/cli.mjs status             # 看登录状态、库内统计、最近运行
node src/cli.mjs schedule install 10:00,20:00
node src/cli.mjs schedule remove
node src/cli.mjs prune [--yes]      # 按当前筛选条件清理历史数据（只标忽略，不删）
node src/cli.mjs reset-browser --yes  # 重置浏览器数据（修复一直拿不到数据）
```

Windows 上双击 `启动.bat` 等同于 `serve --open`。

### 两个「救火」命令

**`prune`** —— 你后来才加上薪资/经验筛选时，之前入库的一批岗位还留在列表里看着碍眼。
这个命令按当前配置回头扫一遍，把不符合的标成「已忽略」。默认只预演不落地，加 `--yes` 才改；
只改状态不删数据，界面里点「重置为未处理」可以逐条恢复。

**`reset-browser --yes`** —— 如果所有页面都变成空白、怎么跑都拿不到数据，
说明浏览器配置脏了（反复被风控后常见）。它会删掉 `browser-profile` 目录，
**岗位数据库不受影响**，只丢登录态，之后重新 `login` 一次即可。

## 换台电脑 / 在家用

```bash
git clone git@github.com:hcr116/boss-jobs.git
cd boss-jobs
npm install          # 只装 playwright-core，十几 MB
```

然后双击 `启动.bat`（或 `npm start`），第一次会要你扫码登录一次。

**不用拷的东西**：数据库、登录态、浏览器 profile 都在 `%APPDATA%\boss-jobs\`，
不在仓库里 —— 所以两台机器各自一份数据，互不干扰，也不会把个人数据传上 GitHub。

> 想在两台机器之间同步"哪些岗位看过/收藏过"，直接拷 `%APPDATA%\boss-jobs\data.db` 过去就行。

## 给别人用

### 方式一：拷文件夹（最简单）

把整个 `boss-jobs` 文件夹（含 `node_modules`）发给对方，对方装好 Node 后双击 `启动.bat`。

第一次运行会要求登录一次，之后各自独立。

### 方式二：打成单文件 exe

```bash
npx esbuild src/cli.mjs --bundle --platform=node --format=esm --outfile=dist/cli.js ^
  --external:playwright-core --external:node:sqlite
```

再用 Node SEA 打包成 exe（体积约 80–120 MB，因为要带 playwright-core 和 Node 运行时）。

> 单文件 exe 只包了程序本身，仍然依赖系统自带的 **Microsoft Edge**（Windows 10/11 都有）。
> 这样做的原因是：用系统真实浏览器带登录态才不会被风控拦，自己下一套 Chromium 反而更容易被识别。

## 常见问题

**Q：提示"未登录"或"无法翻页"？**
登录态过期了。重新 `node src/cli.mjs login`。

**Q：界面一直空着？**
先加一个「搜索配置」，再点「立即抓取一轮」。第一次跑全是新岗位，会抓得久一点。

**Q：抓到的薪资是空的？**
未登录状态下 BOSS 不给薪资。确认 `node src/cli.mjs status` 显示「已登录」。

**Q：会不会翻到同一个岗位好多次？**
同一个 `job_id` 只会入库一次。后续再遇到只更新「最后见到时间」和「见过次数」。

**Q：为什么页面老是自己跳成空白？**
那是 BOSS 的风控跳转。工具走的是接口，不看页面，所以不受影响。

## 技术说明（给想改代码的人）

| 文件 | 作用 |
|---|---|
| `src/cli.mjs` | 命令行入口 |
| `src/scraper.mjs` | 抓取：`ctx.request` 直接打 `/wapi/zpgeek/search/joblist.json`，不解析 DOM |
| `src/db.mjs` | SQLite 数据层与去重逻辑（Node 内置 `node:sqlite`，零原生依赖） |
| `src/server.mjs` | 本地 Web 服务 + API |
| `src/notify.mjs` | Windows Toast 通知 |
| `src/probe-*.mjs` | 开发期的各种探测脚本，可删 |
| `web/` | 前端（原生 JS，无构建步骤） |

关键设计取舍：

- **抓接口不抓 DOM**：列表页会在几秒后被 BOSS 跳成 `about:blank`，DOM 靠不住；接口一次返回完整结构。
- **不自己算签名**：`__zp_stoken__` 等签名参数由浏览器生成并存进 cookie，`ctx.request` 共享同一份 cookie，天然合法。
- **不自己下 Chromium**：用系统 Edge + 你自己的登录态，指纹真实。
